# MedMind — Спецификация «LOCALE-RULES»: региональная корректность контента

> Положить в репозиторий: `docs/LOCALE_RULES_SPEC.md`. Команды — в конце.
> Глобальные правила V3–V7 и BANK_SCALE в силе. Запреты (recalls, парсинг чужих
> банков, публикация без verification passed) действуют.
>
> **Проблема.** Банк Gulf-экзаменов сейчас наполняется переносом NCLEX-вопросов
> (`map_gulf_questions.py`), а NCLEX отражает практику и право США. Часть таких вопросов
> в Заливе имеет **другой правильный ответ** — из-за объёма практики медсестры,
> порядка согласия, правил конца жизни, местных протоколов и культурных норм.
> Вопрос, который учит действию, недопустимому в юрисдикции пользователя, —
> это не «неточность контента», а профессиональный риск для медсестры и репутационный
> для платформы.
>
> **Задача версии.** Ввести юрисдикционный слой: профили правил по каждой стране,
> аудит уже перенесённых вопросов, ограничения генератора, обязательную проверку
> локальным специалистом и явные критерии готовности до запуска трафика.
>
> **Ключевое правило для агента:** местные нормы НЕ утверждать по памяти модели.
> Каждая норма — из официального источника юрисдикции, с URL и датой сверки.
> При недоступности источника норма помечается `status='unverified'` и **не используется
> в генерации** до подтверждения человеком.

## Фаза L1 — Реестр юрисдикционных профилей

### Задачи

- **L1.1 Модель** `JurisdictionProfile` (миграция): `slug` (sa, ae_dubai, ae_abudhabi, qa, om, bh, kw), `country`, `regulator` (SCFHS, DHA, DOH, QCHP, OMSB, NHRA, MOH-KW), `exam_slugs: JSONB` (связь с ExamDefinition), `locale_primary`, `emergency_numbers: JSONB`, `units_system` ('SI'), `verified_at`, `status`.
- **L1.2 Модель** `JurisdictionRule`: `profile_slug`, `domain` (см. таблицу ниже), `rule_key`, `statement` (норма своими словами, кратко), `source_title`, `source_url`, `source_type` ('regulator'|'ministry'|'national_guideline'), `verified_at`, `verified_by` ('agent'|'human_reviewer'), `status` ('unverified'|'verified'|'needs_human'), `divergence_from_us: bool` — отличается ли от практики США/NCLEX.
- **L1.3 Домены, которые обязательно заполнить** (для каждой юрисдикции; агент ищет официальные источники регулятора/министерства и фиксирует найденное; чего не нашёл — `needs_human`):

| Домен | Что выяснить |
|---|---|
| `scope_of_practice` | Что медсестра выполняет самостоятельно, что только по назначению врача; уровни (RN / assistant nurse / specialist) и разница в правах |
| `medication_administration` | Правила введения, кто может назначать/вводить, контроль наркотических средств, требования к двойной проверке |
| `consent` | Кто даёт согласие, роль семьи, особенности для несовершеннолетних и недееспособных |
| `end_of_life` | Порядок оформления отказа от реанимации, кто принимает решение, документирование |
| `documentation_reporting` | Обязательная отчётность (инциденты, инфекции, подозрение на насилие), формы и сроки |
| `infection_control` | Какие национальные стандарты действуют, чем отличаются от CDC-практики |
| `patient_rights` | Национальная карта прав пациента, обращение с жалобами |
| `cultural_religious_care` | Требования к приватности и сопровождению, разделение по полу, участие семьи, время молитвы, пост и приём лекарств, состав препаратов (желатин/этанол) |
| `region_salient_clinical` | Клинические темы, значимые локально (например респираторные инфекции регионального значения, тепловая патология, здоровье при массовых собраниях) |
| `emergency_activation` | Местные номера экстренных служб, порядок вызова внутри учреждения |

- **L1.4 Административная страница** `/admin/jurisdictions`: профили, счётчики норм по статусам, кнопка «отправить на человеческую проверку», отображение просроченных (`verified_at` старше 12 месяцев).

### Приёмка
- Профили созданы для всех 7 юрисдикций реестра экзаменов; по каждому домену есть либо `verified` норма с источником, либо явный `needs_human`; ни одна норма без `source_url` не имеет статус `verified`.

## Фаза L2 — Аудит и карантин уже перенесённых вопросов (КРИТИЧНАЯ)

**Цель:** найти в Gulf-банке вопросы, где правильный ответ юрисдикционно зависим, и убрать их из выдачи до проверки.

### Задачи

- **L2.1 Признак у вопроса**: `jurisdiction_sensitive: bool`, `jurisdiction_verified_for: JSONB` (список профилей, для которых вопрос подтверждён), `origin` ('nclex_mapped'|'gulf_native'|'regional').
- **L2.2 Классификатор** `scripts/audit_jurisdiction_sensitivity.py`: проходит все вопросы, привязанные к Gulf-экзаменам, и помечает `jurisdiction_sensitive=true`, если вопрос затрагивает домены L1.3 (сигналы: тема согласия, отказа от реанимации, объёма практики — «может ли медсестра самостоятельно…», делегирования, обязательной отчётности, вызова экстренных служб, юридических/регуляторных ссылок США — HIPAA, Joint Commission, OSHA, номер 911, названия ведомств США, торговые наименования препаратов, единицы измерения не-SI). Классификация — правила + AI-проверка спорных, результат в отчёт.
- **L2.3 Карантин**: вопросы с `jurisdiction_sensitive=true` и пустым `jurisdiction_verified_for` **исключаются из выдачи по Gulf-экзаменам** (для NCLEX остаются). Реализовать в слое выборки вопросов + тест: карантинный вопрос не попадает в практику, mock и CAT по SNLE/DHA.
- **L2.4 Правка `map_gulf_questions.py`**: перенос запрещён для `jurisdiction_sensitive=true` без явного подтверждения; тест на это правило.
- **L2.5 Отчёт** `/admin/jurisdiction-audit`: сколько вопросов помечено, по домены/экзаменам, сколько в карантине, сколько ожидает локального ревью.

### Приёмка
- Отчёт по аудиту существующего банка получен; карантин работает (тест); повторный прогон маппера не тянет чувствительные вопросы; известное число вопросов, требующих локальной проверки, зафиксировано в PROJECT_STATE.

## Фаза L3 — Локализация генератора

### Задачи

- **L3.1 Инъекция профиля в промпт**: генерация вопроса для экзамена X получает в контекст `JurisdictionProfile` + релевантные `JurisdictionRule` со статусом `verified` (только они!). Промпт-шаблон `prompts/jurisdiction_context.py`.
- **L3.2 Жёсткие ограничения промпта** (перечислить явно):
  - только генерические названия препаратов; торговые наименования — только если подтверждена регистрация в регионе;
  - единицы SI; лабораторные значения — из `lab_reference_values.json` в SI;
  - никаких ссылок на законы, ведомства и стандарты США; вместо них — нормы из профиля;
  - местные номера экстренных служб из профиля;
  - имена и контексты пациентов — регионально нейтральные/уместные (без стереотипизации);
  - вопросы по доменам L1.3 генерировать **только** при наличии `verified` нормы; иначе тему пропустить и записать в дефицит.
- **L3.3 Пост-генерационный линтер** `services/locale_linter.py`: автоматическая проверка сгенерированного вопроса на запрещённые артефакты (regex + список: 911, HIPAA, Joint Commission, OSHA, мг/дл где положено SI, торговые названия из стоп-листа). Провал линтера → вопрос не сохраняется, причина в лог.
- **L3.4 Метка происхождения**: вопросы, сгенерированные с профилем, получают `origin='gulf_native'` и `jurisdiction_verified_for=[profile]` **только после** прохождения Фазы L5 (локальное ревью); до этого — `pending_local_review`.

### Приёмка
- Тест: генерация с профилем `sa` не выдаёт вопрос с «911»/«HIPAA» (линтер блокирует); вопрос по домену без verified-нормы не генерируется; сгенерированные вопросы имеют корректный origin и статус.

## Фаза L4 — Региональный контент и веса blueprint

### Задачи

- **L4.1 Исправить распределение SNLE**: сверить с официальным гайдом SCFHS и привести `ExamDefinition.categories` к официальным весам (по актуальному документу; на момент написания спеки официальный источник указывает Adult Nursing 40% / Maternal-Child 30% / Fundamentals 20% / Management & Leadership 10%, шкала 200–800, проходной 500 — **агент обязан подтвердить по официальному PDF SCFHS и записать `blueprint_verified_at`**). То же для DHA и остальных Gulf-экзаменов.
- **L4.2 Генерация по дефицитам весов**: `plan_generation.py` формирует очередь строго по разнице «целевой вес × целевой объём» минус факт. Приоритет — самый крупный дефицит (ожидаемо Maternal-Child и Management/Leadership для SNLE).
- **L4.3 Целевые объёмы — по критерию целостности mock'а, не по конкуренту**: SNLE — 600 корректно взвешенных вопросов (2 непересекающихся mock'а по 200 + практика), DHA — 450. Значения в конфиге; цели 1200/900 из BANK_SCALE понижаются до этих, дальнейший рост — только после теста спроса (см. L6).
- **L4.4 Модули регионального контента** (по структуре существующих, через верификационный конвейер, источники — регуляторы и национальные гайдлайны):
  - `REG-SA-001` «Практика медсестры в Саудовской Аравии: объём, отчётность, согласие»;
  - `REG-AE-001` «Практика медсестры в ОАЭ (DHA/DOH): регламенты и документация»;
  - `CULT-GULF-001` «Культурно-конгруэнтный уход в странах Залива»: приватность и сопровождение, участие семьи в решениях, пост и приём лекарств, состав препаратов, время молитвы, коммуникация через переводчика;
  - `REG-CLIN-001` «Клинические темы регионального значения» (по домену `region_salient_clinical` профилей).
  - Каждый модуль — с `lay_summary`, привязкой к соответствующим категориям blueprint и вопросами всех поддерживаемых типов.
- **L4.5 Арабский слой**: рационали вопросов Gulf-экзаменов и модули L4.4 переводятся на арабский существующим конвейером с глоссарием; проверка RTL-вёрстки на экране вопроса и в разборе mock'а.

### Приёмка
- `blueprint_verified_at` заполнен для всех Gulf-экзаменов со ссылкой на официальный документ; `/admin/bank-coverage` показывает дефицит < 10% по каждой категории SNLE и DHA при достигнутых объёмах 600/450; 4 региональных модуля импортированы со статусом passed; арабские рационали есть у 100% Gulf-вопросов, выведенных из карантина.

## Фаза L5 — Обязательная проверка локальным специалистом

**Цель:** ни один юрисдикционно-зависимый материал не публикуется без человека, лицензированного в этой юрисдикции.

### Задачи

- **L5.1 Роль рецензента с юрисдикцией**: у `reviewer` добавить `jurisdictions: JSONB` (какие профили вправе подтверждать) и `credentials` (лицензия/страна/квалификация — для публичного профиля `/reviewers/[slug]`).
- **L5.2 Очередь** `/reviewer/queue?jurisdiction=sa`: показывает только материалы, требующие подтверждения по юрисдикциям этого рецензента (карантин L2 + `pending_local_review` L3).
- **L5.3 Расширение рубрики** (к рубрике B4 добавить):
  - `locally_correct: yes | no | uncertain` — соответствует ли верный ответ практике и правилам этой страны;
  - `scope_ok: yes | no` — не выходит ли описанное действие за объём практики медсестры в этой стране;
  - `culturally_appropriate: yes | needs_edit`;
  - `local_note: text` — чем отличается от «международного» ответа.
  - `no` по `locally_correct` или `scope_ok` → вопрос retired + задание на регенерацию с пометкой домена.
- **L5.4 Публикационный шлюз**: вопрос выходит из карантина в выдачу Gulf-экзамена **только** при `locally_correct=yes` от рецензента с соответствующей юрисдикцией. Тест на шлюз.
- **L5.5 Обратная связь в нормы и промпт**: `local_note` рецензента при подтверждении расхождения создаёт черновик `JurisdictionRule` со статусом `needs_human` → после подтверждения источника норма становится `verified` и начинает использоваться генератором. Это и есть механизм, за счёт которого «делать по местному регламенту» становится автоматическим.
- **L5.6 Бейдж**: «Проверено медсестрой, лицензированной в [страна]» на вопросах и модулях; отражение в enterprise-отчётах (аргумент для агентств).

### Приёмка
- Полный цикл: карантинный вопрос → рецензент с юрисдикцией `sa` → `locally_correct=yes` → вопрос появляется в выдаче SNLE; `no` → retired + задание регенерации; `local_note` создал черновик нормы; бейдж отображается.

## Фаза L6 — Шлюз готовности до запуска трафика

**Цель:** формальный чек-лист, до выполнения которого платный трафик и рассылки по Gulf не запускаются.

- **L6.1 Отчёт** `/admin/launch-readiness?exam=snle` — автоматическая проверка, все пункты обязательны:
  1. `blueprint_verified_at` не старше 12 месяцев, источник официальный;
  2. дефицит по каждой категории blueprint < 10%;
  3. объём ≥ целевого (600 SNLE / 450 DHA);
  4. в карантине не осталось вопросов, попадающих в выдачу;
  5. ≥150 вопросов с `human_reviewed` и средним `realism` ≥ 4.0;
  6. 100% юрисдикционно-зависимых вопросов имеют подтверждение локального рецензента;
  7. 2 mock'а собираются без пересечения вопросов;
  8. арабские рационали ≥ 95% выдаваемых вопросов; RTL-проверка пройдена;
  9. дисклеймер о неаффилированности на лендинге экзамена;
  10. E2E-сценарий полного пути по этому экзамену зелёный.
- **L6.2 Флаг** `ExamDefinition.marketing_ready: bool` выставляется вручную только при 10/10; лендинг экзамена до этого — `noindex` и без платного трафика (техническая блокировка, не договорённость).
- **L6.3 Тест спроса до полной готовности разрешён** в ограниченном виде: лендинг + бесплатная демо-практика (без обещаний полноты банка), сбор `paywall_hit` и заявок — чтобы не строить вслепую. Платные кампании — только после `marketing_ready`.

### Приёмка
- Отчёт показывает 10 пунктов с фактическими значениями; `marketing_ready=false` держит лендинг в `noindex`; при выставлении флага без выполнения пунктов — предупреждение в админке.

## Порядок

```
L1 (профили) → L2 (аудит и карантин) → L3 (генератор) → L4 (веса + региональный контент + арабский) → L5 (локальное ревью) → L6 (шлюз)
L2 можно начинать сразу после L1.3 по первому профилю (sa) — не ждать всех семи.
L5 запускать параллельно с L4, как только есть карантин и рецензент.
```

## Сквозные требования

1. Ни одна местная норма не попадает в генерацию без `source_url` и статуса `verified`.
2. Юрисдикционно-зависимый вопрос не публикуется без локального рецензента — автоматика не может выдать это подтверждение.
3. Все пороги и целевые объёмы — в конфиге.
4. PROJECT_STATE.md: раздел «Jurisdictions» — таблица профиль / норм verified / вопросов в карантине / подтверждено локально / launch-readiness (n/10).
