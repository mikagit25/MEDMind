# MedMind AI — Roadmap V4: «Доверие, верификация и двухэтажный лендинг»

> **Как использовать:**
> 1. Положить в репозиторий: `docs/MEDMIND_ROADMAP_V4.md`, закоммитить.
> 2. В Claude Code вставить стартовую команду (раздел «Команды» в конце).
> 3. Фазы выполнять по порядку. Фаза 0 — блокирующая: пока она не закрыта, остальные не начинать.
>
> **Контекст:** Roadmap V3 выполнен (lay-контент, patient-режим AI, публичный SEO-контур, квизы, геймификация, PET, PWA/i18n). V4 — это смена позиционирования: «Медицина, понятная каждому, на его языке» поверх профессионального ядра. Главный принцип V4: **ни одна публичная медицинская страница не существует без проверяемого происхождения контента.**

## Глобальные правила (дополняют правила V3, которые остаются в силе)

1. Перед любой фазой читать `PROJECT_STATE.md`, `docs/MEDMIND_ROADMAP_V3.md` и этот файл.
2. Коммиты с префиксом `feat(v4-phase-N)` / `fix(v4-phase-N)`. После фазы — обновить `PROJECT_STATE.md` (и шапку, и таблицу фаз).
3. `pytest tests/` — 0 failed после каждой фазы (redis-зависимые тесты допустимо маркировать `@pytest.mark.requires_redis` и скипать без Redis). CI на main должен быть зелёным.
4. **Guardrails patient-режима (`prompts/patient_mode.py`) и исключение дозировок из публичных endpoint'ов нельзя ослаблять ни в одной фазе.**
5. Новое правило V4: контент со статусом верификации `failed` или `pending` **не может** отдаваться публичными endpoint'ами и попадать в sitemap.
6. Все пользовательские тексты новых страниц — через словари i18n (en/ru минимум, остальные языки — ключи с английским fallback), не хардкодом.

## Фаза 1 — Конвейер верификации контента (ЯДРО V4)

**Цель:** каждое публичное медицинское утверждение имеет источник, и соответствие источнику проверено автоматически.

### Задачи

- **1.1 Модель происхождения контента.** Добавить к сущностям статей/новостей (и миграцию):
  - `verification_status: enum('pending','passed','failed','human_reviewed')`, default `pending`;
  - `sources: JSON` — список `{title, url, type: 'guideline'|'review'|'study'|'official', accessed_at}`;
  - `verified_at`, `verification_report: JSON` (что проверялось, какие утверждения, результат);
  - `reviewed_by: str | None`, `reviewed_at` — для человеческой рецензии.
- **1.2 Иерархия источников в генерации.** Обновить промпты генерации статей: приоритет — клинические руководства и официальные источники (WHO, NICE, CDC, EMA, национальные гайдлайны), затем систематические обзоры/мета-анализы, и только потом отдельные исследования. Запретить формулировки, выдающие единичное исследование за консенсус («доказано, что…» → «в исследовании X показано…»).
- **1.3 Claim-checker** `backend/app/services/content_verifier.py`:
  - извлекает из статьи фактические медицинские утверждения (числа, дозы-упоминания, причинно-следственные тезисы, рекомендации);
  - сверяет каждое с текстом заявленных источников (загрузка источника + проверка через Haiku: «подтверждает ли источник утверждение — yes/no/partial + цитата места»);
  - любое `no` → статус `failed` + отчёт; всё `yes/partial` → `passed`;
  - запуск: автоматически после генерации + ручной скрипт `verify_articles.py --status pending --max N`, идемпотентный, с dry-run.
- **1.4 Шлюз публикации.** Публичные endpoint'ы статей/новостей и sitemap отдают только `passed`/`human_reviewed`. Существующий опубликованный контент: прогнать верификацию батчами; `failed` — скрыть из публичного доступа и в отчёт `docs/VERIFICATION_BACKLOG.md`.
- **1.5 Кнопка «Сообщить об ошибке».** Endpoint `POST /public/content-feedback` (rate-limited, без auth: article_id, тип проблемы, комментарий, опц. email) + компонент на каждой публичной контентной странице + раздел в админке для разбора.
- **1.6 Тесты:** статус-машина, шлюз публикации (failed не отдаётся), claim-checker на фикстурах (мок AI-вызовов).

### Критерии приёмки
- Ни один публичный endpoint не отдаёт контент со статусом `pending/failed` (тест).
- Верификация прогнана минимум на 50 существующих статьях, отчёт в `VERIFICATION_BACKLOG.md`.
- На публичной странице статьи видны: источники, дата обновления, статус проверки, кнопка «Сообщить об ошибке».

## Фаза 2 — Контроль качества переводов

**Цель:** адекватность переводов измеряется, а не предполагается.

### Задачи

- **2.1 Терминологический глоссарий** `backend/app/data/med_glossary/{lang}.json`: зафиксированные переводы ключевых медицинских терминов (стартово 200–300 терминов на язык, сгенерировать через Claude и сохранить как редактируемый файл). Промпты перевода обязаны использовать глоссарий (вставка релевантных терминов в контекст).
- **2.2 Автопроверки перевода** в `content_verifier.py` (режим translation-check):
  - все числа и единицы (мг/мкг/мл/%) в переводе совпадают с оригиналом;
  - отрицания не потеряны (проверка через Haiku: «совпадает ли направление рекомендации»);
  - термины из глоссария переведены канонически.
  - Несовпадение → `verification_status='failed'` для языковой версии (статус хранить per-language).
- **2.3 Выборочный back-translation:** скрипт переводит 5% случайных абзацев обратно на язык оригинала и сравнивает смысл (Haiku, score 0–1); средний балл и провалы — в отчёт.
- **2.4 Per-language статусы:** языковая версия может быть `failed`, пока оригинал `passed`; публичный роут отдаёт fallback на оригинал/английский с пометкой «перевод на проверке».

### Критерии приёмки
- Тест: перевод с искажённым числом/потерянным отрицанием получает `failed` (фикстуры с моками).
- Глоссарии существуют для всех 7 языков; промпт перевода их использует.

## Фаза 3 — Trust-страницы (E-E-A-T обвязка)

**Цель:** страницы, по которым Google и осторожный пользователь решают, можно ли верить сайту.

### Задачи

- **3.1 Статические страницы** (публичные, локализованные en/ru минимум):
  - `/about` — что за проект, миссия «медицина, понятная каждому, на его языке», кто делает;
  - `/editorial-policy` — методология: иерархия источников → AI-генерация → автоматическая верификация (честно описать claim-checking) → человеческая рецензия для отмеченных страниц; политика обновления контента;
  - `/medical-disclaimer` — полный дисклеймер (вынести единый текст, на который ссылаются все короткие плашки);
  - `/contact`.
- **3.2 Страницы рецензентов** `/reviewers/[slug]`: имя, квалификация, что проверил (связь с `reviewed_by`). Если рецензентов пока нет — страницы-каркас не публиковать, но модель и роут подготовить.
- **3.3 Schema.org:** на контентных страницах `MedicalWebPage` с `dateModified`, `lastReviewed`, `reviewedBy` (когда есть), `citation` из `sources`. Валидировать через структуру JSON-LD в тестах фронта (snapshot).
- **3.4 Футер** всех публичных страниц: ссылки на trust-страницы + дисклеймер-строка.

### Критерии приёмки
- Все 4 страницы доступны без auth, локализованы en/ru, в sitemap.
- JSON-LD валиден (проверка структуры в тесте), `dateModified` берётся из реального поля.

## Фаза 4 — Новый лендинг: двухэтажная модель

**Цель:** лендинг говорит с двумя аудиториями и доказывает ценность интерактивом, а не текстом.

### Задачи

- **4.1 Hero с развилкой:** заголовок в духе «Медицина, понятная каждому. Глубина, которой доверяют специалисты» (финальные формулировки — в i18n-словари, en/ru); два CTA: «Я изучаю медицину» → регистрация/тарифы, «Я хочу разобраться в здоровье» → `/learn` (публичный контур). Видимый переключатель языков в hero-зоне.
- **4.2 Интерактивные блоки:**
  - встроенный мини-квиз (3–5 вопросов из существующих публичных квизов, проходится прямо на лендинге, в конце — ссылка на полный квиз);
  - поисковая строка «Спросите о здоровье простыми словами» → ведёт на страницу публичного глоссария/тем с подстановкой запроса (НЕ прямой вызов AI без auth — лимиты и злоупотребления; AI-ответ доступен после быстрой регистрации, это и есть конверсия).
- **4.3 Блок «Как создаётся наш контент»:** 4 шага конвейера (источники → AI → верификация → рецензия) со ссылкой на `/editorial-policy`; счётчики из API: количество модулей, статей со статусом passed, языков.
- **4.4 Блок для специалистов:** кратко платформа (SM-2, AI-тьютор, vet, drug database) + тарифы.
- **4.5 Производительность:** лендинг — серверные компоненты, без тяжёлого JS выше первого экрана; Lighthouse Performance ≥ 85 mobile, SEO ≥ 95.

### Критерии приёмки
- Лендинг локализован en/ru, оба CTA-пути работают, квиз проходится без регистрации.
- Lighthouse: Performance ≥ 85 (mobile), SEO ≥ 95, Accessibility ≥ 90.
