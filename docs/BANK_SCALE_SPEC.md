# MedMind — Спецификация «BANK-SCALE»: легальное наращивание банка вопросов

> Положить в репозиторий: `docs/BANK_SCALE_SPEC.md`. Команды — в конце.
> Глобальные правила V3–V7 в силе: pytest 0 failed, E2E зелёные, PROJECT_STATE.md,
> верификационный конвейер обязателен, параметры экзаменов из ExamDefinition,
> **recall-вопросы и парсинг чужих банков запрещены** (см. раздел «Границы»).
>
> **Задача версии:** нарастить объём и покрытие банка до конкурентного уровня,
> опираясь на источники с открытыми лицензиями и на человеческую калибровку,
> без правовых рисков и без ущерба позиционированию «проверяемое происхождение».

---

## Границы (читать до начала работы)

**Разрешено:**
- Использовать **факты, темы, структуру и веса** из любых источников — факты и перечни тем не являются охраняемыми объектами.
- Использовать **текст** источников с открытыми лицензиями, разрешающими коммерческое использование (например CC BY), при обязательной атрибуции по условиям лицензии.
- Использовать официальные blueprint'ы и синопсисы экзаменов как структуру.
- Изучать открытые банки конкурентов **как ориентир по покрытию тем и по ожидаемой глубине рационалей** — без копирования и без парсинга.

**Запрещено:**
- Автоматический парсинг/скрейпинг чужих банков вопросов и любое воспроизведение их вопросов, включая перефразированные версии.
- Recall-вопросы («реальные вопросы с экзамена»).
- Использование **текста** источников с лицензиями NC (некоммерческими, напр. CC BY-NC-*) — из них берутся только факты, без переноса формулировок.
- Публикация контента без указания источника и без статуса verification passed.

**Правило для агента:** лицензию каждого источника проверять и фиксировать в БД; при неоднозначности лицензии источник использовать **только как фактическую основу** (факты, без текста) и помечать `text_reuse_allowed=false`. Не предполагать лицензию по памяти — проверять на странице источника.

## Фаза B1 — Реестр источников контента

- **B1.1 Модель** `ContentSource` (миграция): `slug, title, publisher, url, license (строка: 'CC BY 4.0', 'public domain (US gov)', 'unclear' …), license_url, text_reuse_allowed: bool, attribution_template: str, source_type ('reference'|'guideline'|'gov_health'|'official_exam_blueprint'), verified_at, notes`.
- **B1.2 Сид кандидатов** (агент обязан открыть каждый и подтвердить лицензию перед записью; при недоступности — status unclear):
  - StatPearls (NCBI Bookshelf) — крупный клинический справочник, проверить точную лицензию конкретных глав;
  - MedlinePlus (NIH) — потребительский слой;
  - CDC — материалы федерального агентства США;
  - WHO — публикации (внимание: у части материалов лицензия с ограничением коммерческого использования → вероятно `text_reuse_allowed=false`, только факты);
  - NICE guidelines — проверить условия использования;
  - Официальные blueprint'ы: NCSBN Test Plan, SCFHS synopsis, DHA outline и остальные из реестра экзаменов.
- **B1.3 Связка**: у вопросов и уроков (существующее поле `sources`) ссылка на `ContentSource.slug` + конкретный документ/раздел; страница статьи/вопроса выводит атрибуцию по `attribution_template`, где лицензия этого требует.
- **B1.4 Страница `/content-sources`** (публичная, i18n): таблица используемых источников с лицензиями — усиливает E-E-A-T и закрывает вопрос «откуда контент» для B2B.

**Приёмка:** реестр заполнен, у каждой записи проверенная лицензия и дата проверки; вопрос/урок отображает атрибуцию, где требуется; `/content-sources` в sitemap.

## Фаза B2 — Загрузка открытых источников как фактической основы

- **B2.1 Скрипт `ingest_open_sources.py`**: по списку тем (из blueprint категорий) скачивает материалы разрешённых источников через их официальные API/выгрузки (NCBI E-utilities для StatPearls/PubMed; официальные страницы CDC/MedlinePlus), сохраняет в `source_documents` (текст + метаданные + source_slug + hash для дедупликации). Соблюдать rate limits и указывать корректный User-Agent/API-key; никакого обхода ограничений.
- **B2.2 Ограничение по лицензии**: если `text_reuse_allowed=false` — документ сохраняется только для факт-чекинга (генератор получает его как контекст, но промпт обязывает формулировать своими словами и не цитировать), и в `sources` вопроса он указывается как справочный.
- **B2.3 Генерация вопросов из корпуса**: расширить существующий MCQ-генератор режимом `--from-source-docs`: на входе тема + релевантные документы (векторный поиск по pgvector — он у вас включён), на выходе вопрос + rationales к каждому варианту + ссылки на конкретные документы-основания. Далее — существующий claim-checker (V4): каждое утверждение вопроса и рационали сверяется с текстом документа-основания.
- **B2.4 Антидубликаты**: перед записью — проверка семантической близости к существующим вопросам банка (pgvector, порог в конфиге); близкий дубль отклоняется с логом. Это же защищает от непреднамеренного совпадения с чужими формулировками.
- **B2.5 Отчёт прогона**: сколько сгенерировано, сколько отклонено (verification failed / дубль), по каким категориям.

**Приёмка:** прогон на 3 категориях даёт вопросы со ссылками на конкретные документы; claim-checker отклоняет вопрос с искажённым фактом (тест на фикстуре); дубликаты отклоняются.

## Фаза B3 — Gap-анализ покрытия

**Цель:** видеть, где банк тонкий относительно blueprint, и генерировать адресно, а не «побольше вопросов».

- **B3.1 Отчёт `/admin/bank-coverage`**: по каждому экзамену из реестра — таблица: категория blueprint / целевой вес (%) / фактическая доля вопросов (%) / абсолютное число / целевое число (от планового размера банка) / дефицит. Плюс срез по `question_type` (нужное соотношение mcq/sata/ordered/calculation по спеке экзамена) и по `computed_difficulty` из V7 (банк не должен состоять из лёгких вопросов).
- **B3.2 Приоритетная очередь генерации**: скрипт `plan_generation.py` строит задание для генератора из дефицитов (категория, тип, целевая сложность, сколько штук) и складывает в `generation_queue`; воркер генерации берёт задания из очереди.
- **B3.3 Внешний бенчмарк покрытия** (ручной, разово): вручную составить перечень тем сестринского тестирования по официальным blueprint'ам и открытым учебным программам, сверить с вашими категориями, дозаполнить отсутствующие подкатегории. **Только перечень тем, никакого копирования вопросов.**
- **B3.4 Цели по объёму** (в конфиге, ориентир): NCLEX-RN — 2000+, SNLE — 1200, DHA — 900, остальные Gulf — 500 каждый (с учётом переиспользования). Отчёт показывает прогресс к цели.

**Приёмка:** отчёт строится по всем активным экзаменам; очередь генерации заполняется из дефицитов; после прогона воркера дефицит по выбранной категории уменьшается.

## Фаза B4 — Рабочее место рецензента (человеческая калибровка)

**Цель:** внешние медсёстры калибруют банк по реалистичности; их правки улучшают промпт, а не только отдельные вопросы.

- **B4.1 Роль `reviewer`** (существует с V4 — расширить): доступ только к очереди ревью, без остальной админки.
- **B4.2 Очередь ревью** `/reviewer/queue`: вопросы, отсортированные по важности (много показов / health != ok из V7 / новые из генерации / user_flagged). Один экран = один вопрос.
- **B4.3 Анкета (рубрика) — фиксированная, сохраняется в `question_reviews`:**
  - `realism: 1–5` — «насколько похоже на стиль реального экзамена»;
  - `clinical_accuracy: ok|minor_issue|wrong` ;
  - `key_correct: yes|no|ambiguous`;
  - `rationale_quality: 1–5`;
  - `distractors_plausible: yes|some_dead|no`;
  - `language_clarity: 1–5`;
  - `category_correct: yes|no (+ предложенная категория)`;
  - `comment: text` (свободный — самое ценное);
  - решение: `approve | approve_with_edits | reject`.
  - Явная инструкция на экране: «Не воспроизводите вопросы, которые вы видели на настоящем экзамене — это нарушает ваше соглашение с экзаменационным органом. Оценивайте наши вопросы.»
- **B4.4 Действия по итогам**: approve → `human_reviewed`; approve_with_edits → правки применяются с аудитом; reject → вопрос retired + задание на регенерацию (очередь B3.2).
- **B4.5 Обратная связь в промпт (главное!)**: отчёт `/admin/review-insights` — агрегаты по рубрике: средний realism по категориям, частые причины reject, повторяющиеся замечания (кластеризация комментариев через AI, кнопка «сформировать рекомендации к промпту»). Раз в N ревью — ручное обновление промпта генератора; версию промпта фиксировать в `generation_prompt_version` у вопроса, чтобы видеть, улучшают ли новые версии оценки.
- **B4.6 Учёт работы рецензента**: счётчик проверенных вопросов, экспорт для оплаты; страница `/reviewers/[slug]` (V4 Фаза 3.2) — публичный профиль с квалификацией и числом проверенных материалов (с согласия).
- **B4.7 Бейдж на контенте**: «Проверено медсестрой [имя], [квалификация]» на вопросах и модулях со статусом human_reviewed.

**Приёмка:** полный цикл: рецензент вошёл → получил вопрос → заполнил рубрику → reject отправил в регенерацию, approve поставил бейдж; отчёт review-insights агрегирует оценки; версия промпта фиксируется у вопроса.

## Фаза B5 — Фримиум-раскладка (что бесплатно, что за деньги)

**Цель:** бесплатный слой конкурентоспособен с открытыми банками, платный продаёт систему, а не вопросы.

- **B5.1 Бесплатно, без регистрации** (SEO+лидген): практика по категориям с ограничением N вопросов в день (N в конфиге, ориентир 20), rationales видны, публичные квизы, глоссарий, темы, dose-calc тренажёр в демо-объёме. Прогресс не сохраняется — это и есть естественная граница.
- **B5.2 Бесплатно после регистрации**: сохранение прогресса, SM-2 в ограниченном объёме, 1 mock-экзамен, базовый readiness (без разбивки по категориям).
- **B5.3 Платно**: неограниченная практика, полный CAT/mock, readiness с категориями и трендом, план от даты экзамена, разбор mock'а, «объясни иначе» без лимита, офлайн-мобильный, сертификаты, Gulf Bundle, объяснения на своём языке.
- **B5.4 Реализация**: раскладка — в конфиге фичефлагов (не в коде компонентов), чтобы менять границу по данным аналитики; события конверсии (`paywall_hit` с указанием фичи) — в аналитику для оптимизации.
- **B5.5 Честность в UI**: на пейволле указывать, что именно даёт платный уровень, без тёмных паттернов; бесплатный лимит виден заранее, а не после ответа.

**Приёмка:** анонимный пользователь проходит N вопросов и видит корректный пейволл; фичефлаги переключают раскладку без деплоя кода; `paywall_hit` пишется с указанием фичи.

## Порядок

```
B1 (реестр источников) → B2 (загрузка + генерация) → B3 (gap-анализ) → B4 (рецензенты) → B5 (фримиум)
B4 можно начинать параллельно с B2, как только есть кого ревьюить.
B5 — после того как бесплатный слой наполнен (B2–B3), иначе нечего открывать.
```

## Сквозные требования

1. Никакого автоматического обращения к чужим банкам вопросов — ни в скриптах, ни в промптах, ни «для сравнения». Скрипты ingest работают только по источникам из `ContentSource` со проверенной лицензией.
2. Каждый новый вопрос: источники-основания, rationales ко всем вариантам, verification passed, привязка к blueprint-категории, `generation_prompt_version`.
3. PROJECT_STATE.md: раздел «Bank scale» — таблица по экзаменам: вопросов всего / human_reviewed / средний realism / прогресс к цели.
