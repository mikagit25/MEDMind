# MedMind AI — Roadmap V3: «Рост аудитории за пределы специалистов»

> **Как использовать этот файл:**
> 1. Положить в репозиторий: `docs/MEDMIND_ROADMAP_V3.md`, закоммитить.
> 2. Запустить Claude Code в корне проекта.
> 3. Вставить в диалог стартовую команду фазы (готовые команды — в конце файла, раздел «Команды для запуска фаз»).
> 4. Выполнять фазы строго по порядку: каждая следующая опирается на предыдущую.

---

## Глобальные правила для агента (применяются ко ВСЕМ фазам)

1. **Перед началом любой фазы**: прочитать `PROJECT_STATE.md` и этот файл целиком.
2. **После завершения фазы**: обновить `PROJECT_STATE.md` (раздел Completed + Known Fixes), сделать отдельный коммит с префиксом фазы, например `feat(phase-2): patient mode AI`.
3. **Не ломать существующее**: перед изменением любого endpoint'а проверить, кто его использует (frontend, mobile). Все 57+ существующих тестов должны проходить после каждой фазы: `cd backend && pytest tests/ -v`.
4. **Новый код покрывать тестами**: минимум happy path + 1 негативный сценарий на каждый новый endpoint.
5. **Не коммитить секреты.** `.env` файлы не трогать, только `.env.example`.
6. **Медицинская безопасность — приоритет №1**: любой контент и AI-режим для неспециалистов обязан содержать дисклеймер и механизм перенаправления к врачу (детали в Фазе 2). Это требование нельзя ослаблять ради UX.
7. Если объём фазы слишком велик для одной сессии — выполнить часть, обновить `PROJECT_STATE.md` с пометкой «Phase N: in progress, next step: …» и остановиться.

## Фаза 1 — Двухуровневый контент: поле `lay_summary`

**Цель:** один и тот же модуль обслуживает и специалиста, и обычного пользователя.

### Задачи

- **1.1 Схема контента**: добавить в JSON-схему модулей (и в SQLAlchemy-модели + Pydantic-схемы + alembic-миграцию) опциональные поля:
  - `Lesson.lay_summary: str | None` — объяснение темы простым языком, без жаргона, 150–300 слов;
  - `Lesson.lay_glossary: list[{term, simple_definition}] | None` — 3–10 терминов из урока с определениями «для пациента».
- **1.2 Скрипт автогенерации** `backend/app/scripts/generate_lay_summaries.py`:
  - проходит по всем урокам без `lay_summary`;
  - вызывает Claude через существующий `ai_router` (модель уровня Haiku достаточна);
  - промпт-шаблон положить в `backend/app/prompts/lay_summary.py`. Требования к промпту: язык 8-классника, без диагнозов и дозировок, обязательная финальная строка-дисклеймер, формат ответа — строгий JSON;
  - идемпотентность: повторный запуск не перезаписывает уже сгенерированное без флага `--force`;
  - dry-run режим и лимит `--max-lessons N` для контроля расходов API.
- **1.3 API**: `GET /content/lessons/{id}` возвращает новые поля; добавить query-параметр `?view=lay` который отдаёт только упрощённую версию.
- **1.4 Frontend**: на странице урока — переключатель «Профессиональный / Простой язык» (tab или toggle), состояние сохраняется в Zustand.

### Критерии приёмки
- Скрипт сгенерировал lay_summary минимум для модулей BASE-* (бесплатный контур).
- Переключатель работает, упрощённая версия всегда показывает дисклеймер.

## Фаза 2 — Режим «Пациент» в AI-тьюторе (КРИТИЧНАЯ ПО БЕЗОПАСНОСТИ)

**Цель:** пятый AI-режим для неспециалистов с жёсткими guardrails.

### Задачи

- **2.1 Промпт** `backend/app/prompts/patient_mode.py`. Обязательные требования к системному промпту:
  - объяснять простым языком, без латыни и аббревиатур (или расшифровывать их);
  - **НЕ ставить диагнозы**, не подбирать и не корректировать дозировки, не интерпретировать личные анализы как диагноз;
  - при «красных флагах» (боль в груди, признаки инсульта, затруднённое дыхание, мысли о самоповреждении, тяжёлая травма, симптомы у ребёнка до года и т.п.) — первым же предложением рекомендовать немедленно обратиться за экстренной помощью (112/103), и только потом давать общую информацию;
  - каждый ответ завершать коротким дисклеймером «информация образовательная, не заменяет консультацию врача»;
  - на попытки выпросить рецептурную схему лечения — вежливо отказывать и направлять к врачу.
- **2.2 Backend**: добавить режим `patient` в enum режимов `/ai/ask`; роутить на Haiku (дёшево); для этого режима НЕ требовать платный тариф — он доступен на free, но в рамках дневного лимита.
- **2.3 Серверный пост-фильтр**: проверка, что ответ содержит дисклеймер; если нет — дописывать автоматически.
- **2.4 Frontend**: в AI Tutor — выбор режима с понятной подписью («Я не медик — объясни просто»). На мобильном — тот же режим.
- **2.5 Тесты**: pytest-тесты, что (а) режим есть в enum, (б) промпт содержит ключевые guardrail-фразы, (в) пост-фильтр дописывает дисклеймер.

### Критерии приёмки
- Ручная проверка 5 сценариев: обычный вопрос, вопрос про дозировку, «красный флаг», просьба поставить диагноз, вопрос про питомца. Во всех — корректное поведение.

## Фаза 3 — Публичный SEO-контур (главный драйвер просмотров)

**Цель:** контент, видимый без регистрации, индексируемый Google.

### Задачи

- **3.1 Публичные маршруты Next.js** (без auth, SSG/ISR с revalidate ~24h):
  - `/learn/glossary` + `/learn/glossary/[term]` — глоссарий из `lay_glossary` всех уроков (агрегировать, дедуплицировать);
  - `/learn/topics/[slug]` — страница темы: `lay_summary` урока + блок «Изучить глубже» с CTA на регистрацию;
  - `/learn/drugs/[slug]` — публичная карточка препарата из drug database: что это, для чего, основные предосторожности. **Без дозировок** в публичной версии; дозировки — только залогиненным специалистам (как сейчас);
  - `/learn/pets/[slug]` — см. Фазу 6.
- **3.2 Backend**: публичные read-only endpoint'ы `GET /public/glossary`, `GET /public/topics`, `GET /public/drugs/{slug}` — без auth, с агрессивным Redis-кэшем (TTL 1h) и rate limiting по IP.
- **3.3 SEO-обвязка**: `sitemap.xml` (генерируется из публичных страниц), `robots.txt`, метатеги/OpenGraph на каждой публичной странице, JSON-LD разметка `MedicalWebPage` + `DefinedTerm` для глоссария. На каждой странице — видимый медицинский дисклеймер.
- **3.4 Внутренняя перелинковка**: термины глоссария автоматически линкуются внутри lay_summary (простая подстановка по словарю при рендере).

### Критерии приёмки
- `next build` генерирует статические страницы; Lighthouse SEO score ≥ 90 на 3 выборочных страницах.
- Ни одна публичная страница не отдаёт дозировки и платный контент.

- **4.4 Стартовый набор**: создать 5 публичных квизов из существующего контента: «Первая помощь», «Мифы о лекарствах», «Симптомы, которые нельзя игнорировать», «Здоровье питомца: база», «Анатомия для всех».

- OG-картинка результата корректно отображается при вставке ссылки.

## Фаза 5 — Геймификация

### Задачи

- **5.1 Модели**: `UserStreak` (текущий стрик, рекорд, дата последней активности), `XPEvent` (источник: урок/карточка/MCQ, количество). Активность дня = ≥1 завершённое действие.
- **5.2 Начисление XP**: урок 50 XP, верный MCQ 10, повторение карточки 5; уровни по простой формуле (level = floor(sqrt(xp/100))).
- **5.3 Лидерборд**: недельный, по специальности, opt-in (по умолчанию пользователь скрыт), отображать псевдоним.
- **5.4 UI**: стрик-огонёк в шапке dashboard, прогресс-бар уровня, страница лидерборда. Push-уведомление вечером, если стрик под угрозой (расширить существующий планировщик 9 AM).
- **5.5 Mobile**: продублировать стрик и XP на дашборде мобильного приложения (WatermelonDB-синхронизация полей).

### Критерии приёмки
- Стрик корректно работает через границу дня и таймзоны пользователя.
- Лидерборд не показывает пользователей без opt-in.
